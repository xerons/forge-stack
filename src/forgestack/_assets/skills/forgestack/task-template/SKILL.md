# Task Template Sub-skill

Include goal, constraints, and verifiable acceptance criteria. Use the following
fields when they add information; omit empty optional sections and combine fields
for small tasks. Existing project templates take precedence:

```markdown
# Title
# Type (bug | feature | chore | research | refactor)
# Goal
# Source / Grooming Brief
# User Impact
# Requirements
# Constraints
# Acceptance Criteria
# Open Questions
# Dependencies
# Risks
# Suggested Workflow (Planning directly | Research first)
# Optional Specialist Flags (needs-discovery, needs-matt-review, security-sensitive, high-risk)
```

Use plain text/Markdown. Keep cards concise enough that every phase can consume them without wasting context, while preserving all information needed for correctness.
